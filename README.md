## 私について / About Us

### Background & Philosophy

高校時代にBASIC言語に触れたことからプログラミングの歩みを始めました。
前職の航空宇宙関連企業では、安全管理や情報機密保持が極めて重要視される環境に身を置いていました。
そこで培われた「正確さ」と「誠実さ」を、現在はソフトウェア開発における大切な指針としています。

My programming journey began with the BASIC language during my time at a technical high school. 
My subsequent career in the aerospace industry involved working within environments that demanded the highest standards of safety and information security.
The principles of "precision" and "integrity" I embraced there now serve as the core philosophy behind my software development.

### The Mission

親戚のこどもが広告の多いアプリで遊んでいる姿を見て、より健やかなデジタル環境の必要性を感じ、個人開発をスタートしました。
「こどもたちが安心して活用できる、シンプルで誠実なツールを届けたい」という想いから、広告や過剰な演出を排除したアプリ制作に取り組んでいます。

The sight of a young relative playing with apps cluttered with advertisements inspired me to start independent development.
With a mission to "provide simple, honest tools that children can use with peace of mind," I strive to create apps free from intrusive ads and focused on genuine utility.

### こども向け領域について

`kids/` 配下は、こどもが外部サイトへ出られないよう**外部リンクを1本も持たない**構成にしています。

- ハブからも各ゲームからも、TOP・SNS・App Store へのリンクを置いていない
- `_headers` の `/kids*` ブロックが `default-src 'none'` を敷き、外部読み込みを遮断している
- リンクについては CSP で防げないため、`.github/workflows/` の自動検査が担当している

ブラウザゲームのページは英語をメイン、日本語をサブとして表示しています。
`html` の `lang` は `en`（`ja/` のみ `ja`）で、日本語の行には個別に `lang="ja"` を付けています。

例外が3本あります。箱入り娘・KLOTSKI・華容道は、同じパズルを言語ごとに
別のページに分けたもので、それぞれ1言語だけで書かれています。

| ページ | `lang` | 画面の文字 |
|---|---|---|
| `kids/hakoiri-musume/` | `ja` | 日本語だけ（娘・父・母・番頭・丁稚・女中） |
| `kids/klotski/` | `en` | 英語だけ。駒には文字を書いていない |
| `kids/huarongdao/` | `zh-Hant` | 繁体字だけ（曹操・關羽・張飛・趙雲・馬超・黃忠・兵） |

チェス（`kids/chess/`）はもう1つ別の事情を持っています。日英併記のままですが、
**文の種類で扱いを分けています**。見出し・ボタン・駒の名前・棋譜の記号は英語と
日本語を並べ、長い説明文だけ日本語を主にして英語は1行に抑えています。
教材なので文章の量が他の10本とまるで違い、段落ごと併記すると盤が画面から
押し出されるためです。詳しくは下の節に書きました。

盤も駒の構成も3本とも同じです。違うのは名札と色と文言、そして始まりの配置だけなので、
盤を動かす仕組みは `kids/shared/klotski.js` に1本だけ置いて共有しています。
**ここを直すと3本すべてが変わります。** 直したら3本とも開いて確かめてください。

### 時間を計っていません

ブラウザゲームのうち、箱入り娘・KLOTSKI・華容道・川渡りの4本は、
以前あった経過時間の表示を外しました（2026-10-28）。

動いている時計は、こどもにとって「急がなければいけない」という合図になります。
この4本はどれも、盤を眺めて考えることが中身のパズルで、速さを競うものではありません。
記録として残すのも手数だけにしています。

モグラ叩き・MAKE10 のように、制限時間そのものが遊びの骨組みになっているゲームは
対象外です。あちらは時間が無いと成立しません。

#### 03巻だけ、課題の形がちがいます

02巻は「いちばん いい手をさがす」課題で、駒得か詰みで決まるので
唯一の最善であることを機械で証明できました。**序盤はそうではありません。**
`1.e4` と `1.d4` のどちらが良いかには答えが無く、強い人の間でも流行が変わります。

そこで03巻は、1巻と同じ「棋譜を見せて、そのとおりに指す」形だけを使います。
画面に出すのは**「これがこの序盤です」であって「これが最善です」ではありません。**
ここを混ぜると嘘になります。

03巻で**書かない**と決めたもの。

| | 理由 |
|---|---|
| 10手より先の理論 | 解析と流行で変わる |
| 「白が有利」などの評価 | 同上 |
| 「誰が最初に指した」系の逸話 | 出典が曖昧なものが多い |
| ECOコード（C50 など） | 名前と番号は1対1ではなく範囲の対応で、どこまでをその名前と呼ぶかに幅がある |

書くのは、名前のついた序盤の最初の数手（記録が揃っていて確かめられる）と、
記録の残る実戦の全棋譜です。棋譜は事実なので検証できます。解説は自分の言葉で書きます。

検証では、棋譜が最後まで指せることに加えて、**本文に「最善」「有利」と
書いていないこと**も機械で見ています。

03巻の章立てです。

| 章 | 内容 | 問 |
|---|---|---|
| 1 | じょばんの3つのきまり（中央をとる・こまを出す・キングを安全に） | 3 |
| 2 | やってはいけないこと（おなじこまを何度も・早すぎるクイーン・はしのポーン） | 3 |
| 3 | 名前のあるじょばん（イタリアン・ルイロペス・シシリアン・フレンチ・カロカン・クイーンズギャンビット・ロンドン） | 7 |
| 4 | 実戦のきふ（オペラ座の対局） | 2 |

#### 03巻の棋譜

| | 棋譜 | 手数 |
|---|---|---|
| L14（送って読む） | オペラ座の対局（Morphy 対 Duke of Brunswick & Count Isouard、パリ 1858）`1. e4 … 17. Rd8#` | 33 |
| L15（自分で指す） | 上の最後の5手 `Bxd7+ Nxd7 Qb8+ Nxb8 Rd8#` | 5 |

L14 のおしまいで、**残っている駒のねうちは白15・黒25**です。黒のほうが10多い
まま詰みます（白は最後にビショップとクイーンを捨てている）。02巻で教えた
「詰むなら駒の数は関係ない」が、実戦でそのまま出ている局面なので選びました。
この2つの数も機械で確かめています。

#### 02巻の問題は機械で証明しています

答えのある問題は、1問ずつ次の3つを確かめています。

1. その手が**唯一の最善**であること（2番手と差があること）
2. ちゃんと**駒得になる**こと（開始時の駒の差からの増分で測る）
3. 取ったあとが「**詰ませられない駒組み**」にならないこと

**詰みで終わる問題は、詰むところまで指させます。** 最初の手だけで「できた！」にすると、
なぜ詰むのかが盤の上に出ないまま終わり、何が起きたか分からない人が出ます。
今は 2巻の18「なにが ひそんで いる？」（`Rd8+ Rxd8 Rxd8#`）がこの形です。
`win.answers` に「白 黒 白」の順で全部書き、黒の返しは盤が自動で指し、
手ごとの一言を `win.notes` に持ちます。検査では、手が全部指せること、
黒の返しが**唯一の合法手**であること、最後が白のチェックメイトであること、
一言の数が手の数と合うこと、一言が言う駒（f7・g7・h7 の黒のポーン）が盤にあることを確かめます。

3つめは盤をすかすかに作ると静かに起きます。クイーンを取っても、残りが
キング＋ナイト対キングなら引き分けで、教えたことが嘘になります。

**盤はよく作り直しました。** 検証が弾いた、こちらの思い込みの例。

- ピンされた駒は、**ピンの線に沿ってなら動ける**（釘付け役のルークを取り返された）
- 盤がすかすかだと、クイーンが**いつでも逆王手**を見つける
- 白のキングをポーンのうしろに入れたら、今度は**バックランクメイトで白が詰まされた**
- ナイトがどこへどいても開き王手になり、**答えが2つ**になった
- 相手が**1手で両方を受けられる**（Qe7 でクイーンが逃げながらビショップを守る）

このため、ピン・かくれたねらい・そらす の3つは「**見分ける**」回にしてあります。
盤の上で何が起きているかが分かるほうが先で、取るのはそのあとの話だからです。

#### 駒を教える順番

**ポーン → ナイト → ビショップ → ルーク → クイーン → キング**。弱い駒から順です。
外せない理由が3つあります。

1. クイーンを「ルーク＋ビショップ」の一言で済ませたいので、2つが先に要ります
2. **キングは最後でなければなりません。** あの回で教えるのは「ねらわれたマスには
   入れない」で、盤では黒のナイトとポーンが働いています。まだ習っていない駒で
   説明すると、なぜ入れないのかを子ども自身が確かめられません
3. 数の多いポーンが最初なら、実際に指すときの1手目と順番が合います

ルールのいちばん単純なルーク（「たて・よこ」で例外ゼロ）から始める並びも考えましたが、
それだとキングが前に出て 2 が崩れます。ポーンはルールがいちばん複雑な駒なので
最初に置くのは重いのですが、プロモーションとアンパッサンは4章に分けてあり、
ここで教えるのは「前へ1、はじめだけ2、とるのはななめ」の3つだけです。
「とる」そのものの説明も、最初の駒になったポーンの回に置いています。

#### 鍵を掛けていません

**23レッスンすべてが最初から開きます。** 箱入り娘のような開放の仕掛けは置いていません。

進んだ記録はブラウザの中にしか置けず、消えることがあります。
消えたら戻れなくなる作りにはしない、という判断です。
箱入り娘の開放は「もう解ける人への追加」であって無くても遊べますが、
こちらは教材なので、読みたいところを読めないほうが困ります。

`localStorage`（`fdl_chess1_seen`）に置くのは「見たレッスンに ✓ を付ける」だけです。
消えて失われるのは ✓ の見た目だけで、開いているところは変わりません。

そのかわり、指した手は棋譜のテキストとして下に積まれ、**選んでコピーできます**。
ブラウザに頼らず手元に残せる経路を1本だけ用意しています。

#### 英語と日本語の出し方を、文の種類で分けています

切り替えボタンは置いていません（切り替えは状態であり、上と同じ事情です）。

| | 出し方 | なぜ |
|---|---|---|
| 駒の名前・用語・棋譜の記号 | 英語と日本語を並べる | ここは英語が中身です。棋譜の `N` は Knight の N で、並べないと記号の理由が消えます |
| 説明文 | 日本語を主に、英語は短い1行 | 段落まるごとの英訳を並べると文章が2倍になり、狭い画面で盤が下へ押し出されます |

**英語だけ・日本語だけの行は1つも作っていません。** 見出し・説明文・覚えておく一言・
やること・ボタン・できたときの知らせまで、画面に出る文字はすべて両方を持ちます。
分けているのは「どちらを主に見せるか」だけです。

日本語はひらがなを多めにし、漢字そのものを抑えています。ルビは振っていません。

#### 駒は SVG です

Unicode のチェス記号（♔♕♖）は使っていません。白の駒が輪郭だけの字になり、
白いマスの上で読み取りにくいこと、環境によって形が大きく変わることが理由です。
`index.html` の中に `<symbol>` として置いてあり、画像ファイルは1枚も増えていません。

#### ルールの判定は `kids/shared/chess.js` にあります

合法手・チェック・メイト・ステイルメイト・プロモーション・アンパッサン・
キャスリング・50手ルール・千日手・駒不足、そして棋譜（SAN）の読み書き。
画面のことは何も知りません（DOM に触る行が1行もありません）。

続きの巻（02 戦術 / 03 序盤）が同じ判定を使うことが決まっているため、
1ページしか使っていない段階から共通の置き場に置いてあります。
**ここを直すとチェスの全巻が変わります。**

判定は **perft** で確かめてあります。ある局面から n 手先までの合法手の
並べ方を数えた総数で、世界中の実装が同じ値を公表しています。

| 局面 | 深さ | 手数 |
|---|---|---|
| 初期配置 | 5 | 4,865,609 |
| Kiwipete（キャスリングとピンが絡む） | 4 | 4,085,603 |
| アンパッサンで王手が外れる局面 | 4 | 43,238 |
| プロモーションの局面 | 4 | 182,838 |

4局面すべて既知の値と一致しました（2026-10-30）。

**perft は千日手の数え方を見ません。** 千日手に使う局面の見分け札
（`positionKey`）に、空きマスを落として連結する間違いがありました
（駒の並び順さえ同じなら別の局面が同じ札になり、1回しか出ていない
局面に「ひきわけに しよう」が出た）。CPU対戦を作る途中で見つけて直しました
（2026-10-31）。直したあと、ナイトの往復で「2回目は何も出ず、3回目で
主張できる、5回目で自動引き分け」になることを確かめています。
千日手を触るときは、perft とは別にここを確かめてください。

**「詰ませられない駒組み」も総当たりで確かめてあります。** その駒を盤に置ける
並べ方をすべて作り、チェックメイトの形が1つでも存在するかを数えました。

| 駒組み | 並べ方 | 詰みの形 |
|---|---|---|
| キング 対 キング | 7,224 | **0** |
| キング＋ビショップ 対 キング（レッスン20の盤） | 417,228 | **0** |
| キング＋ナイト 対 キング | 429,440 | **0** |
| キング＋ビショップ 対 キング＋ビショップ（同じ色のマス） | 5,858,992 | **0** |
| キング＋ナイト2枚 対 キング | 12,579,944 | 120 |
| キング＋ビショップ 対 キング＋ビショップ（ちがう色のマス） | 5,973,472 | 112 |

下2つに詰みの形があるので、自動の引き分けには**入れていません**。
`chess.js` の `insufficientMaterial` を変えるときは、必ず数え直してください。

レッスン20はこの事実を文章ではなく**遊んで確かめさせます**。白を自分で動かし、
黒は自動で逃げます。駒のくみあわせは、上の表で詰みが 0 だったもののうち3つから選べます。

| 選べるくみあわせ | 盤 |
|---|---|
| キング＋ビショップ 対 キング | `8/8/4k3/8/8/2K5/5B2/8` |
| キング＋ナイト 対 キング | `8/8/4k3/8/8/2K5/5N2/8` |
| おなじ色のビショップどうし | `8/2b5/4k3/8/8/2K5/5B2/8`（c7・f2 とも黒マス） |

**12手で「できた」になりますが、そこで盤を止めません。** 納得するまで指し続けられます。
止めると、確かめている途中で盤が固まることになり、この回の目的と反対になります。
（41万という数字は子どもには意味がないので、画面には出していません）

黒は考えていません。キングが逃げるだけの決まりごとです。詰みの形が存在しない以上
でたらめに動かしても成立しますが、**ステイルメイトを避けるため**に逃げ方を決めてあります。
詰みは存在しなくてもステイルメイトの形は存在するので、でたらめだと自分から隅へ入って
動けなくなり、「詰まないこと」を見せたい回に別の引き分けが割り込みます。
「次に自分が動ける数」をいちばん重く見て、そのうえで白のキングから離れ、盤の中央へ寄ります。
加えて23レッスンについて、盤が読めること・課題が実際に達成できること・
最後の2つの棋譜が本当にチェックメイトで終わることを機械で確かめています。

**ルールやレッスンの盤を変えたら、必ず確かめ直してください。**
確認に使ったスクリプトはこのリポジトリに入れていません（公開されるのは遊ぶファイルだけにしたいため）。

#### レッスンの盤で気をつけたこと

- **キングの回**（L9）… ナイトを黒のポーンに守らせています。守らせないと、
  回り道をせずキングでナイトを取って終われてしまい、
  「ねらわれたマスには入れない」という回の主題が消えます。
- **チェックとにげかたの回**（L15）… あいだに入るマス e4 を、白のポーン（d3）に
  守らせています。守らせないと `Ne4` に `Rxe4+` と取られ、取り返す駒がないまま
  チェックが戻ります。「あいだに入る」を教える回で、あいだに入る手が最悪手に
  なってしまう。**逃げ方を3つ教える盤では、ふさぐ手がただ捨てにならないことを
  必ず確かめてください**（検証スクリプトに入れてあります）。
- **ステイルメイトの回**（L19）… 黒マスのビショップを使っています。
  黒マスのビショップは a8（白マス）を絶対に攻められないので、
  この盤には**チェックメイトが存在しません**。ルークで作るとメイトの解が
  同時に成立してしまい、ステイルメイトの回に詰みの答えが混ざります。

#### 「あそぶ」タブ

| | 中身 |
|---|---|
| ふたりで さす | 1つの画面で白黒とも自分たちで指す |
| コンピュータと さす | 黒を次の `chess-cpu.js` が指す（1巻のレッスン23と同じ相手） |
| ならべて あそぶ | 好きな駒を白黒とも並べてから、ふたりか、コンピュータと指す |

1巻のレッスン23はコンピュータ対戦だけにして、ふたりで指す・並べて遊ぶは
「あそぶ」へ移しました（レッスンの本文から「あそぶ」タブへ案内しています）。

「ならべて あそぶ」の約束です。画面の仕組みは `chess-lessons.js` の `sandbox` 種別です。

- キングは1色1つ。ポーンは1段と8段に置けない。ポーンは8つまで、駒は1色16まで
- 白の番から始まる。**黒が白からチェックされている盤は始められない**
- キャスリングは、キングとルークがはじめの場所にいる組だけできる
  （盤の外の履歴は無いので、場所だけで決めている）
- 棋譜の頭に `[FEN "…"]` を付ける。並べた盤が分からないと読み返せないため
- 指している途中の「やりなおす」は、並べた盤を残して並べ直しに戻る

#### 「コンピュータと さす」の相手は考えません

1巻のレッスン23と「あそぶ」は、白を自分が指し、黒を
`kids/shared/chess-cpu.js` が指します。ルールを覚えた直後に、
勝ち負けを気にせず駒を動かして取る練習をするための相手です。
強さや難しさには触れず、選ぶ画面も置いていません。

先は読まず、上から順に当てはまった規則で指します。

| | 規則 | 中身 |
|---|---|---|
| 1 | 取り返す | 白が直前に取ったマスに利きがあれば、損得を見ずに取り返す |
| 2 | ただ取り | 守られていない白駒を取れるなら取る。複数あればねうちの大きいほう |
| 3 | 守る | 取られそうな黒駒（白に狙われ、黒が守っていない）があれば、逃がすか守りを足す。指したあと取られそうな駒のねうち合計が減る手だけ |
| 4 | それ以外 | 黒の陣地（5〜8段）に留まり、白に狙われたマスへは入らない |

規則の中で候補が複数あれば乱数で選びます。規則4で指せる手が無いときは
「どの段でも安全なマス」、それも無ければ「合法手なら何でも」に落とすので、
合法手が1つでもあれば黒は必ず指します。合法手は `chess.js` が返したものだけを
使い、チェック中の応手もそこで絞られています。

**Stockfish は入れていません。** 強い相手は目的と逆で、弱くしても
「自分からは攻めず、無防備な駒だけ取る」動きにはなりません。
入れる場合は、エンジン部分が GPLv3 であること（このリポジトリは MIT）と、
`/kids*` の CSP に `wasm-unsafe-eval` が要ると考えられること（未確認）が先に決める点です。

検証は手元で、白を乱数で動かした3000局を回しました（スクリプトは入れていません）。
黒が必ず合法手を返し、止まらず、規則の順序と各規則の性質が、検査側で
別に書いた判定と一致しました。

#### 棋譜は2つ載せています

いずれも記録の残っている古い形で、手は事実なので確かめられます。
解説は自分の言葉で書いています。

| | 棋譜 | 手数 |
|---|---|---|
| L21（読む） | スカラーズメイト `1. e4 e5 2. Bc4 Nc6 3. Qh5 Nf6 4. Qxf7#` | 7 |
| L22（指す） | レガールのわな `1. e4 e5 2. Nf3 Nc6 3. Bc4 d6 4. Nc3 Bg4 5. Nxe5 Bxd1 6. Bxf7+ Ke7 7. Nd5#` | 13 |

### 川渡り（River Crossing）について

舟でみんなを向こう岸へ運ぶ古典パズルを4題まとめたものです。

| | 題材 | 舟 | 最短 |
|---|---|---|---|
| 1 | おおかみと やぎと キャベツ | せんどう＋1人 | 7回 |
| 2 | おとなと こども | おとな1人 または こども2人 | 9回 |
| 3 | 3くみの おやこ | 2人乗り・だれでも漕げる | 11回 |
| 4 | 8にんの いかだ | 2人乗り・漕げるのは3人 | 17回 |

手数は「川を渡った回数」です。時間は計っていません（理由は上の節に書きました）。
いずれも幅優先探索で全状態を調べて確かめました。
判定は実装と同じく「渡り終えた後の両岸」だけを見ており、舟の中の組み合わせは見ていません。

3は古くは「嫉妬深い夫」として知られる問題で、漕げる人を親だけに絞ると**解が存在しません**。
総当たりで確かめたうえで、こどもも漕げることにしてあります。
4の原型は警官と泥棒を含む形ですが、こども向け領域なのでせんせいと いぬ に置き換えました。
手数は変わりません。配置や決まりごとを変えるときは、必ず解き直してください。

ルール違反になる手も、舟はいったん渡り切ります。渡った先で何が起きるかを見せてから、
約1.2秒後に自動で引き返します。この回は手数に数えません。

箱入り娘と違い、4題とも最初から選べます。開放の仕掛けは置いていません。

#### 駒と舟の絵（任意）

既定では駒は絵文字、舟は CSS で描いています。
`/images/river-crossing/` に絵を置くと、そちらに入れ替わります。

| | 置くもの |
|---|---|
| 置き場所 | `images/river-crossing/`（`.gitignore` で除外。GitHub には上がらない） |
| 形式 | `.webp`（透過） |
| 駒（16枚） | 正方形 120px。`boatman` `wolf` `goat` `cabbage` `man` `woman` `boy` `girl` `bear-parent` `bear-child` `rabbit-parent` `rabbit-child` `cat-parent` `cat-child` `teacher` `dog` |
| 舟（1枚） | `boat` … 真横から見た空の舟。船体だけを切り出す（560 × 183） |

駒16枚は**同じ枠で切り出してあります**。1枚ずつ輪郭ぴったりに詰めると、
おやぐま と こぐま が画面上で同じ大きさになってしまうためです。

舟は CSS が下端に揃えて敷きます。駒の札がその上に座って見えるかどうかは、
`style.css` の `.boat.has-art` にある幅（210px）と `padding-bottom`（44px）が
絵の舟べりの位置と合っているかで決まります。絵を差し替えたらこの2つを直します。

`man` `woman` `boy` `girl` はステージ2と4で共用します。
ステージ選択のボタンは `wolf` `boy` `bear-parent` `dog` を使い回します。

**クローンしただけでは絵がありませんが、そのまま絵文字で遊べます。**
`images/` が無いことでサイトが再現できない他のページとは、ここだけ事情が違います。
自分で用意した絵を同じ名前で置けば差し替わります。

絵が無いときに出る通信は `boat.webp` への1回だけです。
これが読めなければ残りは読みにいきません（17本の404を並べないため）。
揃っていない絵が一部あった場合は、その駒だけ絵文字に戻ります。
